# Albion Market · 알비온 시장 기록

알비온 **Europe** 서버에서 직접 조회한 네 품목(T7 유물, T8 영혼, T8 유물, T8 룬)의 호가·잔량과 시장 이력을 로컬에 저장하는 Windows 도구입니다. 시간대는 Europe/Paris입니다.

게임 이동·클릭·주문을 자동 실행하지 않습니다. 휴대폰·아이패드 게임 자료는 직접 수집하지 않습니다.

## 시작하기

필요 환경: Windows 10/11, Python 3.11 이상, Npcap. Node.js 22 이상은 선택입니다(있으면 화면 코드를 고쳤을 때 구문 검사 후 반영하고, 없으면 검사만 생략). 최초 설치는 직접 진행합니다.

```powershell
git clone https://github.com/karnbap/albion-market.git
cd albion-market
python -m pip install -r requirements.txt
Copy-Item config.example.json config.json
python setup.py
```

`setup.py`는 공식 Albion Data Client를 `vendor/`에 다운로드하고 품목 숫자 ID를 갱신합니다. Npcap은 [공식 사이트](https://npcap.com/#download)에서 별도 설치합니다. WinPcap API-compatible Mode를 선택합니다.

### 전용 수집기 (선택, 권장)

공식 수집기 0.1.61은 판매 완료 메일을 읽지 못하고(게임 업데이트로 우편함 목록 형식이 바뀜), 구매 주문 메일과 게임의 '내 주문' 목록도 해석하지 않습니다. 이를 고친 로컬 포크를 `vendor/albiondata-client-fork.exe`에 두면 `start.ps1`이 공식 수집기 대신 사용합니다. 포크는 별도 폴더에서 소스로 빌드하며(이 저장소에는 Go 소스를 넣지 않음), 빌드 방법과 바뀐 점은 포크의 `FORK-LOCAL.md`에 있습니다.

- 게임 패킷을 읽기만 합니다. 메일과 내 주문, 거래 완료 탭 목록(local.3부터, `marketorders.finished`)은 `-p`로 지정한 이 컴퓨터의 수신기(private 경로)로만 보내고, 공개 시장 자료에 섞지 않습니다.
- 버전 표시에 `-local`이 붙고, 공식 릴리스로 스스로 업데이트하지 않습니다.
- `setup.py`가 공식 수집기를 다시 받아도 포크 파일은 건드리지 않습니다. 포크를 지우면 다음 실행부터 공식 수집기로 돌아갑니다.
- Windows 스마트 앱 컨트롤이 켜진 PC에서는 새로 빌드한 실행 파일이 막힐 수 있습니다. 임시 폴더(Temp)에 둔 사본은 막혔고, `vendor/`와 빌드 폴더에서는 실행됐습니다(2026-10-26 확인).

분석 화면만 시작:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -DashboardOnly
```

게임을 켤 때 수집도 함께 실행하고, 종료 후 수집만 중단하도록 등록:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\enable-game-watch.ps1
```

화면은 `http://127.0.0.1:18765/`입니다. Windows 로그인 시 감시 프로그램이 시작됩니다. 수집은 게임이 실행 중일 때만 동작하고 게임을 끄면 10초 뒤 수집기만 종료되며, 분석 화면과 기록은 유지됩니다. 게임 중 분석 프로그램이 응답하지 않으면 감시 프로그램이 다시 켭니다. 화면 상단에 자동 감시 상태가 표시되고, 감시 프로그램이 꺼져 있으면 경고가 나옵니다. 수동 수집은 `start.ps1`, 수동 종료는 `stop.ps1`을 사용합니다.

## 사용 방법

1. 유럽 서버에 접속하고 구역을 이동해 도시를 인식시킵니다.
2. 게임 시장에서 품목별 판매·구매 요청서 목록과 필요한 페이지를 엽니다. 분석 화면의 수동 조회 버튼은 필수가 아닙니다.
3. 시장 이력은 24시간·7일·4주를 각각 조회합니다.
4. 거래 메일을 열면 도시·품목·단가·수량을 별도 저장합니다. 같은 메일을 다시 열어도 중복 집계하지 않습니다. 수집기는 켜진 뒤 받은 우편함 목록으로 메일을 해석하므로, 메일을 열기 전에 우편함을 한 번 열어 주세요. 게임 도중 수집기를 다시 켰다면 지역도 한 번 이동하세요. 전용 수집기는 판매 완료·판매 만료·구매 주문 완료·구매 주문 만료 메일을 모두 읽습니다. 공식 수집기 0.1.61은 지금 게임에서 메일을 읽지 못합니다.
5. 실제 게임 화면과 수신 가격·수량을 대조합니다. 암호화·게임 프로토콜 변경·조회 누락 때문에 수신되지 않을 수 있습니다.

## 가격과 통계 해석

- 호가는 **조회 당시 일부 주문의 잔량**입니다. 전체 주문이나 현재 최저·최고를 항상 보장하지 않습니다. 단일 주문 수신은 최고/최저 미확인으로 표시합니다.
- 소량·대량·물량 벽과 가까운 가격대의 물량 기준 가격을 따로 표시합니다.
- 오래된 자료는 보관하되 현재 매매 후보에서 제외합니다.
- 시장 이력은 시간 구간의 평균가와 총량입니다. 개별 최고 체결가·가격별 정확한 체결량으로 해석하지 않습니다.
- 내 판매 메일은 시장 통계와 별도인 누적 근거입니다. 요일·24시간·7일 시장 거래량에 더하지 않습니다. 전용 수집기는 게임이 메일을 보낸 때('메일 받은 때')도 함께 보내고, 공식 수집기 메일에는 처음 읽은 때만 있습니다.
- **구매 주문 완료·만료 메일**은 판매 통계(시장별 합계·누적 최고 단가·시세표의 보라색 표시)에 섞지 않고 '내 구매 주문 · 만료 메일' 칸에 따로 보여 줍니다. 판매 만료 메일의 팔린 수량도 판매 통계에 더하지 않습니다.
- 메일 실버 금액은 세금을 빼기 전 금액입니다. 공식 수집기가 보내던 고정 세율(3%) 세후 금액은 실제 입금액으로 사용하지 않습니다.
- 매매 후보는 수수료·세금·운송비 가정을 사용한 검토 자료입니다. 창고 재고는 모르며, 기존 주문은 내 매물 탭에 적어 둔 것만 반영합니다.
- 매매 후보는 방식별로 따로 계산합니다. **바로 매입**(매도 요청서에서 바로 구매)은 수수료가 없고, **바로 판매**(매수 요청서에 바로 판매)는 판매세만, **주문 매입·주문 판매**는 설정 수수료까지 반영합니다. 표는 품목마다 상위 15개를 보여 줍니다.
- 화면 맨 위 **지금 하세요**는 지금 할 만한 거래 1·2·3순위를 개수·가격·투자금·예상 이익과 함께 보여 줍니다. 바로 사고파는 거래는 양쪽 호가를 가격대별로 따라가며 실제로 이익이 나는 수량만 세고, 매도 주문으로 파는 거래는 하루 판매량, 주문으로 사는 거래는 하루 판매량의 4분의 1까지만 셉니다. 설정의 '한 거래에 쓸 최대 실버'(기본 1,000만)를 넘지 않습니다. 확실성(바로 체결 > 매도 주문 대기 > 싹쓸이 > 양쪽 주문 대기)과 레드존·안개 경유 위험을 반영해 순위를 매기며, 두 순위가 같은 매도 목록에서 사거나 같은 도시의 같은 구매자에게 팔지 않게 합니다. 판매 이력이 없는 싹쓸이는 순위에 넣지 않습니다.
- **카를레온(Caerleon)과 브레실리엔(Brecilien)은 기본으로 거래 분석에서 뺍니다.** 카를레온은 레드존(죽으면 짐을 모두 잃는 지역), 브레실리엔은 안개 지역을 지나야 하고, 두 도시의 가격 차이는 대부분 그 운반 위험이 가격에 붙은 것이라 이익으로 계산하면 늘 순위 위에 올라옵니다. 설정 탭의 '거래 분석에서 뺄 도시'에서 바꿀 수 있으며, 뺀 도시도 시장 상세 탭의 시세에는 그대로 보입니다.
- **기록은 지워지지 않습니다.** 시장 호가·이력·메일은 `data/market.sqlite3`에 계속 쌓입니다. 다만 거래 계산은 설정의 '호가 유효 시간'(기본 15분, 최대 60분) 안에 본 호가만 쓰므로, 시간이 지나면 지금 하세요·매매 후보가 비게 됩니다. 이때 지금 하세요는 마지막 추천을 흐리게 보여 주고, **기록** 탭에 최근 30일 추천이 시각별로 남습니다.
- 시장 목록을 열 때마다 최저 매도가·최고 매수가·보이는 물량을 10분 단위로 저장해 **요일·시간대별 평균 호가와 쌓인 물량**(시장 상세 탭)을 만듭니다. 추천할 때 지금 요일·시간대의 판매 속도와 매수·매도가를 평소와 비교해 보여 주고, 매도 주문으로 파는 추천은 오늘 요일의 판매 속도(평소의 0.8~1.2배)를 순위에 반영합니다. 요일·시간은 설정의 시간대(Europe/Paris) 기준이며, 화면 위에는 내 컴퓨터 시각도 함께 표시합니다.
- 지금 하세요는 두 칸으로 나뉩니다. **바로 사고 바로 팔기**는 매도 요청서에서 즉시 사서 다른 도시 매수 요청서에 즉시 파는 거래만, **주문 넣고 기다리기**는 매수·매도 주문을 걸어 체결을 기다리는 거래(바로 사서 매도 주문, 양쪽 주문, 싹쓸이 후 재등록)만 각각 1·2·3순위로 보여 줍니다. 매매 후보 탭도 같은 기준으로 거를 수 있습니다.
- **시간대별 수요 조심**: 최근 28일 1시간 단위 판매 기록을 평일·주말로 나눠 시간대별 판매 속도를 구하고, 앞으로 6시간·24시간 예상 판매량을 계산합니다. 기다리는 거래는 앞으로 24시간 예상 판매량을 넘게 잡지 않으며, 앞으로 6시간이 평소의 60% 아래(예: 평일 새벽)면 '주문을 한꺼번에 쌓지 마세요' 경고와 함께 순위를 낮춥니다. 시장 상세 탭에도 예상 판매량과 수요가 적은 시간을 보여 줍니다. 게임에서 24시간 시장 이력을 자주 열수록 정확해집니다.
- **전략 연구** 탭은 시장(품목 × 거래 도시)마다 평일·주말 평균 체결가와 하루 판매량, 즉시 구매 비율(판매량 중 매도 주문이 팔린 몫, 같은 시간대 최고 매수가·최저 매도가 사이 위치로 추정), 체결 관찰(다시 연 시장에서 같은 주문의 남은 수량이 줄어든 양), 최저가가 깎이는 간격, 평일 매수 주문 → 주말 매도 주문의 수수료 후 차익을 보여 줍니다. 수수료(매수·매도 주문 각 2.5% + 판매세)가 커서 평일·주말 평균가 차이만으로는 손해인 경우가 많고, 싸게 매수 주문으로 모으고 비싸게 매도 주문을 거는 차이가 핵심입니다.
- 나머지 화면은 **도시별 · 매매 후보 · 싹쓸이 · 전략 연구 · 시장 상세 · 내 매물 · 내 판매 메일 · 기록 · 설정** 탭으로 나뉩니다.
- **매매 후보**와 **싹쓸이**는 유효 시간(15분) 안에 연 시장이 없어 지금 결과가 비면, 마지막으로 결과가 있던 목록을 '지난 후보 · 지난 분석'으로 그때 시각과 함께 보여 줍니다. 그때 가격·잔량이라 지금은 바뀌었을 수 있으니, 거래 전에 게임에서 그 시장을 다시 열어 확인해야 합니다.
- **내 매물** 탭: 게임 시장 창의 **내 주문** 탭(매도·매수)을 열면 거기 보이는 주문을 자동으로 등록하고(‘자동’ 표시), 다시 열 때마다 남은 수량을 고치며, 같은 도시·종류 목록에서 사라진 주문(다 팔림·취소·만료)은 정리합니다. 게임의 내 주문 탭은 지금 서 있는 시장의 주문만 보여 주므로, 정리도 그 도시·종류 안에서만 합니다. 위치가 `1000-HellDen`인 시장은 림허스트와 같은 주문 번호를 보여 주므로(2026-10-27 실제 게임에서 확인) 내 주문과 시장 자료 모두 림허스트로 묶습니다. 목록이 비어 있으면 그 도시·종류의 주문을 모두 정리하고, 한 쪽(50개)이 꽉 찬 목록은 다음 쪽에 더 있을 수 있어 정리하지 않습니다. 시장 목록을 열 때도 남은 수량·내 앞 물량·최저가 여부를 갱신합니다. 전용 수집기는 내 주문 목록을 개인 토픽 `marketorders.mine`으로 따로 보냅니다. 공식 수집기는 내 주문 목록을 일반 시장 자료와 똑같이 보내므로, 대체 수단으로 수집기를 디버그 기록(`-debug -operations 81,82,94,174,175,176`)으로 켜고 그 기록(`vendor/albiondata-client.log`)에서 ‘내 주문 목록 요청’(작업 번호 94) 바로 뒤에 온 자료를 내 주문으로 구분합니다. 어느 쪽이든 이 자료는 시장 호가에 넣지 않습니다. 자동 인식이 안 될 때는 품목·도시·가격·수량을 직접 적을 수 있고, 그 시장을 열면 같은 주문에 연결됩니다. 시장 상세 호가표에는 내 주문 가격에 '내 주문' 표시가 붙습니다.
- **오래 안 팔린 매물 · 기다릴까 고칠까**(내 매물 탭): 남은 수량이 마지막으로 줄어든 때(없으면 이 프로그램이 처음 본 때)부터 3일이 지난 내 매도 주문마다 세 가지를 매수 기록의 평균 원가와 비교합니다. 그대로 기다리면 내 앞 물량과 내 수량이 다 팔리는 예상 일수(새로 더 싼 매물이 끼어들지 않는다고 본 최소 일수), 최저가보다 1실버 낮게 다시 올리면 새 가격에 다시 내는 주문 수수료와 예상 일수, 지금 매수 주문에 팔면 받는 금액입니다. 팔리는 속도는 하루 판매량(24시간·7일·28일 중 가장 느린 값)에, 알 수 있으면 즉시 구매 비율을 곱합니다. 추천은 이미 최저가면 기다리기, 3일 안에 내 차례면 기다리기, 고치면 원가 아래면 기다리기, 판매량 이력이 없으면 판단 보류, 그 밖에는 가격 고치기이며, 개당 얼마를 덜 받는 대신 며칠 빨라지는지 함께 보여 줍니다.
- **마을별 보유량**(내 매물 탭): 도시·품목마다 시장에 올린 것(내 매도 주문의 남은 수량), 은행에 넣어 둔 것, 거래 완료 탭에 있는 것(내가 사서 아직 찾지 않은 것)을 더한 실제 보유량과, 매수 기록의 평균 원가로 계산한 금액을 보여 줍니다. 은행은 수집기가 읽지 못해 직접 적습니다(0이면 지움). 거래 완료 탭은 전용 수집기(local.3부터)가 게임 시장 창에서 그 탭을 열 때마다 받으며, 항목의 매수자가 나이고 아직 안 찾은 것만 셉니다(캐릭터 ID는 해시로만 비교). 그 탭을 마지막으로 연 때 기준이라, 물건을 찾은 뒤에는 탭을 다시 열어야 줄어듭니다.
- **매수 기록 · 평균 매수가**(내 매물 탭): 추적 품목을 산 기록과 품목별 평균 매수가(최근 30일·전체)를 보여 줍니다. 구매 주문 완료 메일(실제 지출액), 구매 주문 만료 메일(실제로 산 수량 × 주문 단가), 아직 열려 있는 내 매수 주문에서 채워진 수량은 자동으로 들어옵니다. 열린 주문은 같은 시장·같은 가격의 구매 메일이 주문 뒤에 오면 그 메일로 대신합니다(같은 가격의 열린 주문이 둘이면 둘 다 메일로 대신한 것으로 봄). 시장 매도 목록에서 바로 산 것은 수집기가 볼 수 없으니 직접 적습니다(바로 사기 / 매수 주문, 산 때는 설정 시간대 기준). 원가는 매수 주문으로 산 만큼 설정의 주문 수수료를 더한 값입니다.
- 매매 후보·지금 하세요는 같은 시장에 남아 있는 **내 기존 주문을 고려**합니다. 기다리는 거래의 추천 수량에서 내 남은 매도(매수) 수량만큼 빼고, 내 기존 매도 가격보다 싸게 올리라는 추천에는 '내 기존 주문이 뒤로 밀림' 경고와 함께 순위를 낮춥니다(×0.7). 싹쓸이 분석은 내 매물을 사들이는 계산에서 뺍니다.
- **내 판매 메일** 탭은 모든 도시·품목의 판매 완료 메일, **내 구매 주문 · 만료 메일**, **메일 수집 진단**을 보여 줍니다. 진단은 수집기의 개인 자료 통로로 들어온 횟수(메일·내 주문 목록), 메일마다 저장·무시·오류 결과와 이유, 수집기 기록(`vendor/albiondata-client.log`)의 메일 관련 줄을 보여 줍니다. 메일이 안 쌓이면 여기서 원인을 먼저 확인하세요. 맨 아래 **수집기 원본 기록**에는 디버그 기록에서 읽은 우편함 목록·메일 열기·내 주문 요청 줄이 나옵니다. 공식 수집기 0.1.61이 메일을 열 때마다 'Mail Info is not valid'를 남기고 버리는 것은, 게임 업데이트로 우편함 목록의 자료 위치가 바뀌어 목록을 해석하지 못하기 때문입니다(2026-10-26 실제 패킷으로 확인). 전용 수집기에서 고쳤습니다.
- **사서 되팔 때 수량 경고**는 최근 24시간·7일·28일 판매량을 하루 단위로 바꿔 가장 느린 값을 기준으로 삼습니다. 하루치보다 많이 사면 '조금 위험', 3일치를 넘기면 '위험'입니다. 관측 시간이 짧은 기간(24시간은 6시간 미만, 7일·28일은 24시간 미만)은 빼고, 이력이 없으면 '판매량 미확인'으로 표시합니다. 매매 후보·도시별 정리·선택한 시장의 판매 흐름·싹쓸이 분석에 함께 나옵니다.
- **매물 싹쓸이 분석**은 유효 시간 안의 매도 목록에서 싼 매물부터 사들였을 때 최저가가 어디까지 오르는지 단계별로 계산합니다. 산 물건을 새 최저가보다 1 실버 싸게 다시 올려 모두 팔았을 때의 예상 이익(설정 수수료·판매세 반영)을 구하고, 하루 판매량 3일치를 넘지 않는 단계 중 이익이 가장 큰 단계를 보여 줍니다. 본 매도 목록 범위 밖 가격은 쓰지 않으며, 다른 판매자가 더 싸게 올리거나 수요가 없으면 이익이 사라집니다.
- **오늘 도시별 정리**는 도시마다 여기서 사서 팔 곳, 여기서 바로 팔기 가장 비싼 품목, 바로 사기 가장 싼 품목, 다시 열어볼 시장을 보여 줍니다. 유효 시간 안의 호가만 쓰며, 비교할 도시가 2곳 이상일 때만 최고·최저를 표시합니다.

## 설정과 저장

`config.json`은 개인 설정이며 Git에서 제외됩니다. 예시 세율·수수료는 게임 계정에서 확인하고 확인 항목을 체크해야 합니다. `data/market.sqlite3`에는 호가·이력·내 거래 메일·내 주문이 저장됩니다. `vendor/`에는 다운로드한 수집기와 (있으면) 전용 수집기가 있습니다. 이 폴더들은 공유하지 않습니다.

일반 자료는 `-i http://127.0.0.1:18765/ingest/europe`, 개인 자료(거래 메일 `marketnotifications`, 내 주문 목록 `marketorders.mine`)는 `-p http://127.0.0.1:18765/private/europe`로만 전달합니다. 공식 AODP 서버로는 보내지 않습니다. private 경로로 중복 전달되는 일반 호가 사본은 무시하고, `marketorders.mine`은 private 경로에서만 받습니다.

화면은 5초마다 갱신하고, 브라우저 탭이 숨겨져 있으면 갱신을 멈춥니다. `data/server.log`는 오류 위주로 남기며 5MB씩 최대 3개까지 보관합니다. 분석 코드와 웹 파일의 로컬 변경은 검증 후 자동 반영합니다. **GitHub 변경을 자동 내려받는 기능은 아닙니다.** 협업 변경은 검토 후 `git pull`로 받아야 합니다. 실행·감시 스크립트 변경은 다음 실행 시 적용합니다.

분석 보고서를 SMTP로 보내는 선택 기능은 기본 꺼짐입니다. 수신자·발송 시간·계정은 로컬 설정으로 지정하고, 비밀번호는 `ALBION_SMTP_PASSWORD` 환경변수에 둡니다. 게임 내 거래 메일 수집과 SMTP 보고서는 별개입니다.

## 개발·검증

```powershell
python -m unittest discover -s tests -v
node --check web/app.js
```

단위 검사는 임시 DB를 사용하며 게임·운영 DB를 조작하지 않습니다. 기존 운영 DB가 있는 경우 `python debug_market.py`로 읽기 전용 복제 점검을 실행할 수 있습니다. 생성되는 보고서는 로컬에만 남습니다.

협업 범위·주의점·남은 검증은 [팀 인수인계](docs/TEAM_HANDOFF.md)를 참고하세요. 변경은 작업 브랜치와 Pull Request로 검토하는 방식을 권장합니다.

## 외부 구성요소

[Albion Online Data Project](https://github.com/ao-data/albiondata-client)의 공식 클라이언트를 별도 다운로드해 사용합니다. 전용 수집기는 그 0.1.61 태그를 고친 로컬 포크로, 이 저장소 밖에서 빌드합니다. 이 저장소는 해당 프로젝트의 공식 서비스가 아니며 외부 실행 파일·Npcap을 재배포하지 않습니다. 외부 구성요소의 라이선스는 각 프로젝트를 따릅니다.

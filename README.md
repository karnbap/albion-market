# Albion Trade Master · 알비온 시장 기록

알비온 **Europe** 서버에서 직접 조회한 품목(T7 유물, T8 영혼, T8 유물, T8 룬, 테스트 중인 착취한 에너지)의 호가·잔량과 시장 이력을 로컬에 저장하는 Windows 도구입니다. 시간대는 Europe/Paris입니다.

`config.json`의 `trial_items`에 넣은 품목은 **테스트·보류**로 표시됩니다. 수집하고 시장 상세·매매 후보(도시별 묶기 포함)·싹쓸이에 보이지만, '지금 하세요' 추천과 투자 비율·매매 계획에서는 뺍니다. 착취한 에너지(`UNIQUE_GVGTOKEN_GENERIC`, 품목 번호 9877)가 처음 들어간 테스트 품목입니다. 물량 기준(소량·대량·물량 벽)은 유물에 맞춰져 있어, 하루 수십만 개가 거래되는 에너지에서는 경고가 덜 정확할 수 있습니다.

`item_cities`는 품목별 예외 도시입니다. 설정 탭에서 뺀 도시(`excluded_cities`)라도 여기 적은 품목에는 다시 넣어 분석합니다. 기본값은 착취한 에너지에 브레실리엔(5003)을 넣습니다(옐로우존 미스트로 오갈 수 있고, 에너지는 브레실리엔이 가장 큰 시장이라서). 다른 품목은 그대로 브레실리엔을 뺍니다.

게임 이동·클릭·주문을 자동 실행하지 않습니다. 휴대폰·아이패드 게임 자료는 직접 수집하지 않습니다.

## 시작하기

필요 환경: Windows 10/11, Python 3.11 이상, Npcap. Node.js 22 이상은 선택입니다(있으면 화면 코드를 고쳤을 때 구문 검사 후 반영하고, 없으면 검사만 생략). 최초 설치는 직접 진행합니다.

```powershell
git clone https://github.com/karnbap/albion-market.git
cd albion-market
python -m pip install -r requirements.txt
Copy-Item config.example.json config.json
python setup.py
```

`setup.py`는 공식 Albion Data Client를 `vendor/`에 다운로드하고 품목 숫자 ID를 갱신합니다. Npcap은 [공식 사이트](https://npcap.com/#download)에서 별도 설치합니다. WinPcap API-compatible Mode를 선택합니다.

### 전용 수집기 (선택, 권장)

공식 수집기 0.1.61은 판매 완료 메일을 읽지 못하고(게임 업데이트로 우편함 목록 형식이 바뀜), 구매 주문 메일과 게임의 '내 주문' 목록도 해석하지 않습니다. 이를 고친 로컬 포크를 `vendor/albiondata-client-fork.exe`에 두면 `start.ps1`이 공식 수집기 대신 사용합니다. 포크는 별도 폴더에서 소스로 빌드하며(이 저장소에는 Go 소스를 넣지 않음), 빌드 방법과 바뀐 점은 포크의 `FORK-LOCAL.md`에 있습니다.

- 게임 패킷을 읽기만 합니다. 메일과 내 주문, 거래 완료 탭 목록(local.3부터, `marketorders.finished`), 인벤토리·은행 수량(local.4부터, `holdings.containers`), 내 즉시 구매(local.5부터, `marketorders.instantbuy`)는 `-p`로 지정한 이 컴퓨터의 수신기(private 경로)로만 보내고, 공개 시장 자료에 섞지 않습니다.
- 버전 표시에 `-local`이 붙고, 공식 릴리스로 스스로 업데이트하지 않습니다.
- `setup.py`가 공식 수집기를 다시 받아도 포크 파일은 건드리지 않습니다. 포크를 지우면 다음 실행부터 공식 수집기로 돌아갑니다.
- Windows 스마트 앱 컨트롤이 켜진 PC에서는 새로 빌드한 실행 파일이 막힐 수 있습니다. 임시 폴더(Temp)에 둔 사본은 막혔고, `vendor/`와 빌드 폴더에서는 실행됐습니다(2026-10-26 확인).

분석 화면만 시작:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -DashboardOnly
```

게임을 켤 때 수집과 분석 프로그램을 함께 실행하고, 게임을 끄면 함께 끄도록 등록:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\enable-game-watch.ps1
```

화면은 `http://127.0.0.1:18765/`입니다. Windows 로그인 시 감시 프로그램이 시작됩니다. 수집은 게임이 실행 중일 때만 동작하고 게임을 끄면 10초 뒤 수집기, 분석 화면 창, 분석 프로그램을 차례로 끕니다. 기록은 그대로 남고 다음에 게임을 켜면 다시 켜집니다. Claude 대화 탭에서 답을 만드는 중이면 답이 끝난 뒤에 끕니다. 게임을 켜지 않고 직접 연 분석 프로그램은, 그 뒤에 게임을 켰다 끄기 전까지는 끄지 않습니다. `stop.ps1`로 직접 끈 날은 자동으로 다시 켜거나 끄지 않습니다. 게임 중 분석 프로그램이 응답하지 않으면 감시 프로그램이 다시 켭니다. 게임을 켜면 분석 화면을 주소창 없는 Edge 개별 창으로 한 번 띄우되, 게임 화면을 가리지 않게 작업 표시줄에 최소화해 둡니다(이미 열려 있으면 그대로 둠). 창은 수집기를 기다리지 않고 분석 프로그램이 응답하면 바로 띄웁니다. 수집기가 Windows 보안(스마트 앱 컨트롤)에 막히면 창에 그 상태가 나오고, 처음 10분은 1분마다, 그 뒤는 5분마다 다시 시도합니다(PC를 켠 직후 몇 분 막혔다 풀린 적이 있음). 바탕화면 '알비온 시장 분석' 바로가기도 같은 창을 열거나 앞으로 가져옵니다(`dashboard_window.py`, Edge가 없으면 기본 브라우저). 화면 상단에 자동 감시 상태가 표시되고, 감시 프로그램이 꺼져 있으면 경고가 나옵니다. 수동 수집은 `start.ps1`, 수동 종료는 `stop.ps1`을 사용합니다.

## 사용 방법

1. 유럽 서버에 접속하고 구역을 이동해 도시를 인식시킵니다.
2. 게임 시장에서 품목별 판매·구매 요청서 목록과 필요한 페이지를 엽니다. 분석 화면의 수동 조회 버튼은 필수가 아닙니다.
3. 시장 이력은 24시간·7일·4주를 각각 조회합니다.
4. 거래 메일을 열면 도시·품목·단가·수량을 별도 저장합니다. 같은 메일을 다시 열어도 중복 집계하지 않습니다. 수집기는 켜진 뒤 받은 우편함 목록으로 메일을 해석하므로, 메일을 열기 전에 우편함을 한 번 열어 주세요. 게임 도중 수집기를 다시 켰다면 지역도 한 번 이동하세요. 전용 수집기는 판매 완료·판매 만료·구매 주문 완료·구매 주문 만료 메일을 모두 읽습니다. 공식 수집기 0.1.61은 지금 게임에서 메일을 읽지 못합니다.
5. 실제 게임 화면과 수신 가격·수량을 대조합니다. 암호화·게임 프로토콜 변경·조회 누락 때문에 수신되지 않을 수 있습니다.

## 가격과 통계 해석

- 호가는 **조회 당시 일부 주문의 잔량**입니다. 전체 주문이나 현재 최저·최고를 항상 보장하지 않습니다. 단일 주문 수신은 최고/최저 미확인으로 표시합니다.
- 소량·대량·물량 벽과 가까운 가격대의 물량 기준 가격을 따로 표시합니다.
- 오래된 자료는 보관하되 현재 매매 후보에서 제외합니다.
- 시장 이력은 시간 구간의 평균가와 총량입니다. 개별 최고 체결가·가격별 정확한 체결량으로 해석하지 않습니다.
- 내 판매 메일은 시장 통계와 별도인 누적 근거입니다. 요일·24시간·7일 시장 거래량에 더하지 않습니다. 전용 수집기는 게임이 메일을 보낸 때('메일 받은 때')도 함께 보내고, 공식 수집기 메일에는 처음 읽은 때만 있습니다.
- **구매 주문 완료·만료 메일**은 판매 통계(시장별 합계·누적 최고 단가·시세표의 보라색 표시)에 섞지 않고 '내 구매 주문 · 만료 메일' 칸에 따로 보여 줍니다. 판매 만료 메일의 팔린 수량도 판매 통계에 더하지 않습니다.
- 메일 실버 금액은 세금을 빼기 전 금액입니다. 공식 수집기가 보내던 고정 세율(3%) 세후 금액은 실제 입금액으로 사용하지 않습니다.
- 매매 후보는 수수료·세금·운송비 가정을 사용한 검토 자료입니다. 창고 재고는 모르며, 기존 주문은 내 매물 탭에 적어 둔 것만 반영합니다.
- **운송비**는 도시 사이 텔레포트비로 계산합니다(`travel.py`): 150 × 무게(kg) × 품목 배수 × 서버 배수 × 경로 거리. 무게와 품목 배수는 게임 자료(ao-bin-dumps items.xml)에서 한 번 받아 `data/item_data.json`(`gamedata.py`)에 둡니다. 장비·영혼·유물은 배수 1이고, 자원은 티어·인챈트가 높을수록 커집니다(T8.4 가죽은 256). 경로 거리는 이웃한 왕립 도시끼리 1(테트포드–포트 스털링–림허스트–브리지워치–마틀록–테트포드), 그 밖의 왕립 도시끼리 2, 브레실리안이 끼면 2입니다. 공식은 팬 사이트(Albion Free Market)가 분석한 것이라 공식 자료가 아닙니다. 그래서 서버 배수(기본 1.156)는 설정에서 게임 이동 계획 금액에 맞춰 확인해야 합니다. 예: T8 영혼 100개 브레실리안 → 림허스트 금액 ÷ 30,000. 설정의 추가 운송비는 그 위에 더하고, 캐얼리언처럼 텔레포트 경로가 없거나 무게를 모르면 추가 운송비만 들어갑니다. 무게 자료가 없거나 배수를 확인하지 않았으면 "운송비 설정 미확인"이 표시됩니다. 품목 시세의 원가 칸에서 **가져갈 도시**를 고르면 도착 원가를 봅니다.
- 매매 후보는 방식별로 따로 계산합니다. **바로 매입**(매도 요청서에서 바로 구매)은 수수료가 없고, **바로 판매**(매수 요청서에 바로 판매)는 판매세만, **주문 매입·주문 판매**는 설정 수수료까지 반영합니다. 표는 품목마다 상위 15개를 보여 줍니다.
- 화면 맨 위 **지금 하세요**는 지금 할 만한 거래 1·2·3순위를 개수·가격·투자금·예상 이익과 함께 보여 줍니다. 바로 사고파는 거래는 양쪽 호가를 가격대별로 따라가며 실제로 이익이 나는 수량만 세고, 매도 주문으로 팔거나 주문으로 사는 거래는 그 시장 하루 판매량의 **내 몫**(설정, 기본 20%)까지만 셉니다. 나머지는 다른 판매자·구매자 몫으로 봅니다. 설정의 '한 거래에 쓸 최대 실버'(기본 1,000만)를 넘지 않습니다. 확실성(바로 체결 > 매도 주문 대기 > 싹쓸이 > 양쪽 주문 대기)과 레드존·안개 경유 위험을 반영해 순위를 매기며, 두 순위가 같은 매도 목록에서 사거나 같은 도시의 같은 구매자에게 팔지 않게 합니다. 판매 이력이 없는 싹쓸이는 순위에 넣지 않습니다.
- **카를레온(Caerleon)과 브레실리엔(Brecilien)은 기본으로 거래 분석에서 뺍니다.** 카를레온은 레드존(죽으면 짐을 모두 잃는 지역), 브레실리엔은 안개 지역을 지나야 하고, 두 도시의 가격 차이는 대부분 그 운반 위험이 가격에 붙은 것이라 이익으로 계산하면 늘 순위 위에 올라옵니다. 설정 탭의 '거래 분석에서 뺄 도시'에서 바꿀 수 있으며, 뺀 도시도 시장 상세 탭의 시세에는 그대로 보입니다.
- **기록은 지워지지 않습니다.** 시장 호가·이력·메일은 `data/market.sqlite3`에 계속 쌓입니다. 다만 거래 계산은 설정의 '호가 유효 시간'(기본 15분, 최대 60분) 안에 본 호가만 쓰므로, 시간이 지나면 지금 하세요·매매 후보가 비게 됩니다. 이때 지금 하세요는 마지막 추천을 흐리게 보여 주고, **기록** 탭에 최근 30일 추천이 시각별로 남습니다.
- 시장 목록을 열 때마다 최저 매도가·최고 매수가·보이는 물량을 10분 단위로 저장해 **요일·시간대별 평균 호가와 쌓인 물량**(시장 상세 탭)을 만듭니다. 추천할 때 지금 요일·시간대의 판매 속도와 매수·매도가를 평소와 비교해 보여 주고, 매도 주문으로 파는 추천은 오늘 요일의 판매 속도(평소의 0.8~1.2배)를 순위에 반영합니다. 요일·시간은 설정의 시간대(Europe/Paris) 기준이며, 화면 위에는 내 컴퓨터 시각도 함께 표시합니다.
- 지금 하세요는 두 칸으로 나뉩니다. **바로 사고 바로 팔기**는 매도 요청서에서 즉시 사서 다른 도시 매수 요청서에 즉시 파는 거래만, **주문 넣고 기다리기**는 매수·매도 주문을 걸어 체결을 기다리는 거래(바로 사서 매도 주문, 양쪽 주문, 싹쓸이 후 재등록)만 각각 1·2·3순위로 보여 줍니다. 매매 후보 탭도 같은 기준으로 거를 수 있습니다.
- **시간대별 수요 조심**: 최근 28일 1시간 단위 판매 기록을 평일·주말로 나눠 시간대별 판매 속도를 구하고, 앞으로 6시간·24시간 예상 판매량을 계산합니다. 기다리는 거래는 앞으로 24시간 예상 판매량을 넘게 잡지 않으며, 앞으로 6시간이 평소의 60% 아래(예: 평일 새벽)면 '주문을 한꺼번에 쌓지 마세요' 경고와 함께 순위를 낮춥니다. 시장 상세 탭에도 예상 판매량과 수요가 적은 시간을 보여 줍니다. 게임에서 24시간 시장 이력을 자주 열수록 정확해집니다.

- 품목 시세의 **원가 계산** 칸: 고른 티어·인챈트·품질을 살 때의 개당 원가를 두 가지로 보여 줍니다. 매수 걸어 사기 = 최고 매수가보다 1 높게 건 값 + 주문 수수료(설정), 즉구 = 최저 매도가(수수료 없음). 도시마다 가장 최근 기록을 쓰고, 하루 안의 기록이 있으면 그중 가장 싼 도시, 없으면 오래된 기록 중 가장 싼 도시를 고릅니다. 품질을 '아무 품질'로 두면 가장 싸게 즉구할 수 있는 품질 기준으로 비교합니다(매수 주문은 같은 품질끼리만 경쟁). 수량을 적으면 합계와 차이도 보이고, 즉구 수량이 최저가 물량보다 많으면 알려 줍니다. 운송비는 넣지 않습니다.
- 원가 칸의 **만들어 올리기 원가**: 인챈트(.1~.3)나 보통보다 높은 품질을 고르면, .0을 사서 직접 올릴 때의 원가를 완성품 값과 나란히 보여 줍니다(`upgrade.py`, `Store.craft_cost`). 원가 = .0 가격 + 품질 재굴림 평균 비용 + 인챈트 단계마다 재료(룬·영혼·유물) 개수 × 최저가. 품질은 .0일 때 먼저 올립니다. 재굴림 1회 비용 = 품목 가치 × 현재 품질 배수(보통 4.4, 좋음 5.5, 뛰어남 6.6, 훌륭함 27.5)이고, 품목 가치는 인챈트마다 두 배가 되기 때문입니다. 재굴림 확률(예: 보통 → 좋음 80%, 좋음에서 그대로 30%)과 배수는 위키(wiki.albiononline.com/wiki/Quality) 기준이고, 평균은 실패해서 그대로 남는 경우까지 넣은 기댓값입니다. 시작 품질(보통부터 목표 품질까지)마다 .0을 사 보고 가장 싼 길을 고릅니다. 매수 걸어 모으기와 즉구로 모으기를 따로 계산합니다. 인챈트 재료 개수와 품목 가치는 게임 자료(`gamedata.py`)에서 옵니다. 게임의 할인이 재굴림 값을 바꾸므로, 설정의 품질 재굴림 비용 배수를 수리대 금액에 맞춰 둡니다. 재료를 여러 도시에서 살 때의 운송비는 넣지 않습니다.

  - 이름 목록은 처음 검색할 때 ao-bin-dumps `formatted/items.json`(약 24MB)을 한 번 받아 `data/item_names.json`(약 1MB)으로 줄여 둡니다.
- **시세 감시** 탭: 고른 품목(추적 품목은 빠른 추가, 다른 품목은 품목 시세의 '시세 감시에 추가')마다 거래 분석 도시의 바로 사기(가장 싼 도시의 최저 매도), 매수 걸어 사기(최고 매수보다 1실버 위에 주문을 걸 값이 가장 싼 도시, 최근 거래가 있는 도시 우선), 걸어 팔기(최저 매도가 가장 높은 도시, 매도 주문을 가장 비싸게 걸 수 있는 곳), 바로 팔기(최고 매수)를 10초마다 다시 읽습니다. 값이 바뀐 칸은 잠깐 빛납니다. 도시마다 내가 연 시장·실시간 공유·공개 서버 중 더 새 값을 쓰고, 하루 넘은 값은 뺍니다.
  - 알림 가격을 적으면 바로 사기 값이나 매수 걸 값이 그 값 이하이거나 걸어 팔기 값이 그 값 이상(팔 때)이 되는 순간 한 번 알립니다. 가짜 알림을 막으려고 걸어 팔기 값에서는 도시 최저가가 내 매도 주문인 도시와, 가운데 도시의 2배를 넘는 튀는 값을 빼고, 스트림 값보다 싼 공개 서버 값(하루 안)이 있으면 그 값을 씁니다. 매수 걸 값은 거꾸로 내 매수가 1등인 도시와 가운데 도시의 절반에 못 미치는 값을 빼고, 더 높은 공개 서버 값을 씁니다. 그래도 그 사이 팔린 매물이 남아 있을 수 있으니 올리기 전에 게임에서 확인하세요. 품목마다 1000만 실버 투자 예측도 함께 나옵니다. 들려온 매물을 싼 값부터 이익이 남는 데까지 사서 걸어 팔기 도시에 걸었을 때의 수익률과 순이익(판매세·등록 수수료 포함), 그리고 그 도시의 최근 7일 거래량 × 매도 주문 몫 × 내 몫(`cycle_share`)으로 잡은 판매 기간입니다. 7일 안에 못 팔 양이면 7일에 맞는 투자금도 보여 줍니다. 매수 걸어 사기 예측은 도시마다 최고 매수보다 1실버 위에 걸어 7일 안에 채워질 어림 수량(그 도시 거래량 × 매수 주문 몫 × 내 몫)만큼 사고 주문 수수료를 더한 값입니다. 내가 연 시장과 공유 스트림, 공개 API 답을 모두 `data/lookup.sqlite3`에 저장해 더 최신 쪽을 쓰고, 나중에 다시 훑은 자료에서 사라진 매물은 뺍니다. 거래량은 내 PC가 받은 기록(추적 품목, 품질 1)이 공개 기록보다 새로우면 그쪽을 씁니다: 화면 오른쪽 아래 알림, 소리, 데스크톱 알림(허용했을 때), 탭 배지. 소리와 데스크톱 알림은 따로 끌 수 있고 브라우저에 기억합니다. 소리를 끄면 데스크톱 알림도 소리 없이 보냅니다. 조건이 풀렸다가 다시 맞으면 또 알립니다.
  - 투자 예측 아래에는 걸 도시의 하루·주간·월간·시간당 거래량, 시간대별 막대, 값별 비교표가 나옵니다. 최근 7일 시간별 거래에서 시간 평균가가 그 값 이상이었던 시간의 거래량을 그 값에 팔린 양으로 보고, 거기에 내 몫을 곱해 7일 판매량과, 바로 샀을 때와 매수 걸어 샀을 때의 순이익을 계산합니다. 시간 평균이라 개별 체결가와는 다른 어림값입니다.
  - 알림은 1시간 안의 값에서만 울립니다. 더 오래된 값이 조건에 맞으면 표에만 '충족 · N시간 전 값'으로 표시합니다.
  - 분석 창이 열려 있어야 알림이 옵니다(최소화는 괜찮지만, 브라우저가 숨은 창의 갱신을 늦출 수 있습니다). 감시 목록은 `data/market.sqlite3`의 `watches` 표에 저장하며 최대 40개입니다.

## 설정과 저장

`config.json`은 개인 설정이며 Git에서 제외됩니다. 예시 세율·수수료는 게임 계정에서 확인하고 확인 항목을 체크해야 합니다. `data/market.sqlite3`에는 호가·이력·내 거래 메일·내 주문이 저장됩니다. `data/lookup.sqlite3`에는 품목 시세용 공개 주문(하루치)이, `data/item_names.json`에는 품목 이름이 있습니다. `vendor/`에는 다운로드한 수집기와 (있으면) 전용 수집기가 있습니다. 이 폴더들은 공유하지 않습니다.

일반 자료는 `-i http://127.0.0.1:18765/ingest/europe`, 개인 자료(거래 메일 `marketnotifications`, 내 주문 목록 `marketorders.mine`)는 `-p http://127.0.0.1:18765/private/europe`로만 전달합니다. 공식 AODP 서버로는 보내지 않습니다. private 경로로 중복 전달되는 일반 호가 사본은 무시하고, `marketorders.mine`은 private 경로에서만 받습니다.

화면은 5초마다 갱신하고, 브라우저 탭이 숨겨져 있으면 갱신을 멈춥니다. 내 매물·매수 기록·은행 입력 칸을 쓰는 동안에는 갱신과 새 버전 다시 열기를 미뤄 고르던 값이 풀리지 않게 합니다. 표는 안쪽 세로 스크롤 없이 페이지 하나로 스크롤됩니다. `data/server.log`는 오류 위주로 남기며 5MB씩 최대 3개까지 보관합니다. 분석 코드와 웹 파일의 로컬 변경은 검증 후 자동 반영합니다. **GitHub 변경을 자동 내려받는 기능은 아닙니다.** 협업 변경은 검토 후 `git pull`로 받아야 합니다. 실행·감시 스크립트 변경은 다음 실행 시 적용합니다. `auto_update.py`와 `lookup.py`(공개 스트림 수신) 변경도 분석 프로그램을 다시 시작해야 적용됩니다.

분석 보고서를 SMTP로 보내는 선택 기능은 기본 꺼짐입니다. 수신자·발송 시간·계정은 로컬 설정으로 지정하고, 비밀번호는 `ALBION_SMTP_PASSWORD` 환경변수에 둡니다. 게임 내 거래 메일 수집과 SMTP 보고서는 별개입니다.

## Claude 대화 탭

프로그램 안에서 이 컴퓨터의 Claude Code에게 시세·재고·주문을 물어봅니다. 처음 한 번 터미널에서 `claude auth login`으로 로그인해야 합니다. 쓴 만큼 Claude 요금제 사용량에서 차감됩니다.

- **읽기만 합니다.** 파일 읽기·찾기와 `market_tools.py`의 시세 조회만 허용하고, 명령 실행·파일 수정·다른 MCP 연결은 주지 않습니다. `config.json`과 `data/`는 직접 읽지 못하게 막습니다.
- **보내는 자료.** 질문을 보낼 때 현재 상태를 `data/chat/snapshot.json`에 씁니다(접속 토큰·메일 주소·호가 전체·거래 메일 원문은 뺌). 질문과 Claude가 읽은 내용은 답을 만들기 위해 Anthropic으로 전송됩니다. 공식 AODP 서버로는 보내지 않습니다.
- **대화 저장.** 대화는 `data/chat.sqlite3`에 남고 Git에서 제외됩니다. 답은 서버에서 만들어지므로 탭을 옮기거나 새로고침해도 이어집니다. 답 하나는 10분이 지나면 멈춥니다.
- `chat.py`를 고치면 분석 프로그램을 다시 시작해야 반영됩니다. `market.py`와 달리 자동 반영되지 않습니다.

## 개발·검증

```powershell
python -m unittest discover -s tests -v
node --check web/app.js
```

단위 검사는 임시 DB를 사용하며 게임·운영 DB를 조작하지 않습니다. 기존 운영 DB가 있는 경우 `python debug_market.py`로 읽기 전용 복제 점검을 실행할 수 있습니다. 생성되는 보고서는 로컬에만 남습니다.

협업 범위·주의점·남은 검증은 [팀 인수인계](docs/TEAM_HANDOFF.md)를 참고하세요. 변경은 작업 브랜치와 Pull Request로 검토하는 방식을 권장합니다.

## 외부 구성요소

[Albion Online Data Project](https://github.com/ao-data/albiondata-client)의 공식 클라이언트를 별도 다운로드해 사용합니다. 전용 수집기는 그 0.1.61 태그를 고친 로컬 포크로, 이 저장소 밖에서 빌드합니다. 이 저장소는 해당 프로젝트의 공식 서비스가 아니며 외부 실행 파일·Npcap을 재배포하지 않습니다. 외부 구성요소의 라이선스는 각 프로젝트를 따릅니다.
